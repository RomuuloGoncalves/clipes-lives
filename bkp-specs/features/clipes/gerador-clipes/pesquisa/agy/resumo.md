# Resumo Executivo: Recomendações e Divergências (Abordagem Original vs. CPU Local)
1. **Divergência central (Whisper API + LLM no VOD inteiro -> Triagem Multimodal 1 Hz + ASR Cirúrgico):** Transcrever 4h de live na nuvem é pago e lento em CPU; além disso, texto puro é cego a sustos, gritos, gargalhadas e explosões de chat em lives de GTA VI/reações.
2. **Ingestão híbrida (Streamlink + yt-dlp + Chat Sem Login):** Mantenha `streamlink` só para captura de chunks em LIVE (ring buffer de 90s); para VODs, `Most Replayed` e chat do YouTube use `yt-dlp` (*audio-first*), e para chat de VOD da Twitch use GraphQL público (`kimne78kx3ncx6brgo4mv6wki5h1ko`) em 8 threads.
3. **Estágio 1 — Detecção de picos 100% CPU em <2 min por hora de live (Zero ASR/LLM):** Combine a 1 Hz quatro sinais gratuitos com bônus de concordância (+15% quando >=2 sinais batem >=0,5), reaproveitando a arquitetura MIT do `utkualsir/sharkyclips` (nov/2026):
   - **Chat (peso 0,30):** Taxa em 5s vs. mediana móvel de 121s com teto Poisson z-score, teto por autor único, regex pt-BR (`KKKK`, `LUL`, `caralho`, `clipa`) e **shift de -5s** para compensar o atraso de digitação.
   - **Eventos vocais em CPU (peso 0,25):** Modelo ONNX INT8 `CED-mini` (~10 MB via `sherpa-onnx`, 200x tempo real em CPU sem PyTorch) ou `YAMNet` para separar risada e grito real de tiros/música do jogo.
   - **Loudness / Sustos (peso 0,20):** Excesso de RMS dB sobre mediana de 60s (mascarando silêncio <-55 dB) + salto abrupto sobre os últimos 3s para capturar *jumpscares*.
   - **Consenso externo em VOD (peso 0,10):** Heatmap `Most Replayed` do YouTube (`yt-dlp --dump-json`) e densidade de clips de viewers da Twitch quando disponíveis.
4. **Estágio 2 — Transcrição local só nos Top 15–25 picos (`faster-whisper` INT8):** Substitua a Whisper API paga pelo `faster-whisper` (`small` ou `large-v3-turbo`, `compute_type="int8"`, `word_timestamps=True`, Silero VAD com `min_silence_duration_ms=600`) rodando apenas nas janelas de 90s ao redor dos picos (10–15 min de CPU total).
5. **Divergência no corte (Timestamps de LLM -> Word & Silence Snapping determinístico):** LLMs alucinam números de tempo e cortam frases ao meio; use o algoritmo determinístico de `_snap_start`/`_snap_end` nos timestamps das palavras (+2,0 para `.?!`, +1,5 para pausa >=0,8s, 6–12s de *pre-roll* para o *setup* e proteção até a risada acabar).
6. **Papel do LLM (Opcional, nunca para achar timestamps brutos):** Em CPU sem GPU, descarte o LLM no caminho crítico; se usar Ollama local (`qwen3.5:4b`), use-o só para dar título/gancho aos Top 10 candidatos ou citar a frase inicial/final (com *reverse-alignment* no Whisper, padrão `xixihhhh/hotclip`).
7. **Enquadramento 9:16 e Legendas Baratas em CPU:** Evite rastreamento facial pesado frame a frame em lives de jogo; use layout bipartido fixo (webcam no topo + gameplay embaixo, estilo `clips-studio`/`openshorts`) ou detecção esparsa a 2 fps (`160x90`, padrão `mehbul/chopify`) + legendas `.ass` via `ffmpeg/libass`.
8. **Avaliação Rápida sem Renderizar Vídeo:** Valide pesos e regras de borda em <1s na CPU sobre `signals.npz` + `words.json` cacheados de 4 VODs, exigindo `MidWordCutRate = 0%`, `SentenceEdgeRate >= 85%`, posição do pico entre 35%–75% do clipe e `Recall@10 >= 0,75` contra `Most Replayed`/Twitch Clips.
9. **Código-base para reaproveitar já (MIT):** Copie `scorer.py`, `candidates.py`, `signals/chat.py`, `signals/loudness.py` e `signals/laughter.py` do [`utkualsir/sharkyclips`](https://github.com/utkualsir/sharkyclips) e o pipeline *audio-first* + `captions.py` do [`mehbul/chopify`](https://github.com/mehbul/chopify).
10. **Resultado esperado:** Custo R$ 0, zero login/API key, processamento 6x–10x mais rápido em CPU que transcrever a live inteira, e clipes de 20–60s que preservam *setup*, clímax e reação sem palavras cortadas.
